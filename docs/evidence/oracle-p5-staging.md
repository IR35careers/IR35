## Public HTML caching and CSP (explicitly scoped change)

The Oracle-only staging gateway opts into a60s bounded4MB homepage cache ONLY for anonymous direct GET `/`, no query/cookie/Authorization/RSC/prefetch/action/range. It strips caller personalization/internal headers from that upstream public request; never caches Set-Cookie, compressed, error or partial HTML. Only inline scripts/styles already carrying the ORIGINAL random request nonce get exact SHA256 sources. The public cached header contains NO nonce source, so cached nonce attributes are inert; injected un-nonced scripts are NOT blessed. Parser-inserted external script permission is narrowed to exact-origin `/_next/static/` and the GA loader, not all same-origin uploads. No script unsafe-inline/eval fallback. The private/member/auth/API CSP retains fresh nonce + strict-dynamic. Framework nonce is now forwarded in the request CSP, as Next requires. Any transform failure preserves uncached original policy, not a weakened fallback. Actual browser CSP/hydration/MISS/HIT evidence is STILL REQUIRED, not inferred from unit tests.

Rationale: [Next nonce documentation](https://nextjs.org/docs/app/guides/content-security-policy) requires dynamic rendering and forbids ordinary shared nonce HTML caching. [Self-hosting](https://nextjs.org/docs/app/guides/self-hosting) supports standalone/image/data-cache operation but does not magically cache dynamic responses. This conservative public-only transform needs actual tests before activation; Vercel never runs this gateway. Staging Basic protection itself prevents public CDN distribution; on-VM caching is the rehearsal target, not a claimed production header fix.
